# Example authoring and verification

The playable BASIC files are in [examples](../../examples/README.md). These helpers maintain their compact artwork, source code and illustrations.

- `build_flight_simulator.py` generates Vol radar / Radar Flight 0.5. A standalone BASIC routine builds the 24 × 20 terrain from a map number; printing and collision checks share it. The editable 8 × 8 palette is in `flight-simulator-assets.json`. Two 52-byte offset-224 DATA strings and a 40-byte mountain atlas keep the program compact. Dense public line numbers save branch-operand bytes; `source(labels=True)` exposes the logical-to-public mapping for diagnostics. Scalars freed after printing hold tower request target/deadline/count; G(64) becomes the wind-band flag. The reserve is 99, with a 2-point outer-band surcharge and exempt runways. Random altitude/radar requests allow six clear-weather steps and give 20 score points; storms pause their deadlines. The landing score is 100 + 5*fuel - steps + 20*completed requests. RELOC and REPEAT both call radar; ignored Canon function keys use the debounced KHELD byte at &H1999. The input helper detects release before the next press. Procedural maps, recurrent water-biased storms, proportional paper sprites and quarter-cell radar positions remain autonomous on the Canon.
- `build_3d_maze.py` generates the French and English LCD maze with stackless random depth-first generation, confirmation-key timing as additional entropy, two drawing strings covering 148 corridor configurations, seven fixed LCD patterns and a shared wall/monster slot with three distance sprites. Every game starts at a junction with at least three internal passages. The monster follows the player within three passage steps and wanders outside that range; unseen monsters pause before contact at a blind bend. Fragments appear as a native dot two cells away or character 197 one cell away. All four fragments can be collected in LCD-only mode; optional printing labels the column/row borders, reuses the map array as a fast tile palette, then restores the world and LCD banks.
- `build_s70_quest.py` generates the French and English Quest files from `s70-quest-assets.json` and the LCD sprite catalogue.
- `update_paper_games.py` contains the shared native-byte encoding and Ruins direction selector, along with the paper-row conversion helpers.
- `build_byte_font.py` generates Studio’s hexadecimal DATA-byte badge font.
- `render_s70_quest.py` and `export_s70_quest_sprites.py` prepare guide images and editable sprite examples.
- `validate_*.py` checks native encoding, ROM execution, game startup, printed rows and movement. Tests use developer-supplied Canon ROMs; controlled fixtures are described in each script.

Generated reports and intermediate files remain in the ignored `build/` directory. The firmware build pipeline is documented in [tools/firmware](../firmware/README.md).
