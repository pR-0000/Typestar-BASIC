# Firmware regression checks

These suites exercise the BASIC ROM and HD6301 core. Generated binaries, disassembly maps and reports belong in the ignored `build/` directory. Original Canon ROMs are supplied locally by the developer.

Run `run_release_audit.py` after the incremental firmware build. It runs ROM layout/data checks, BASIC, memory, serial and state suites, followed by waveform, glyph, tile-row and game checks. `tools/firmware/prepare_release_candidate.py` requires sixteen passing reports for the exact 0.4.100 CPU-image hash before packaging socket images.

`validate_buzzer_survey_v3.py` also provides the instruction-timing oracle used by the sound regressions. `validate_quest_*.py` drives actual tokenized game rules with controlled fixtures. The [audit notes](../../docs/firmware-test-0.4.100.md) describe coverage and physical-test boundaries.

Exploratory recording analyses and standalone sound-survey firmware are archived in the ignored local development tree. They are separate from the regression entry point.

`evaluate_flight_routes.py` independently searches calm interior routes for all 999 maps, including the guide's four-step takeoff, climb/forest fuel and runway alignment. It also computes an optimistic lower bound for a perimeter-only journey with all useful speeds, free heading changes and optional free east wind on every step. The current reserve is 99 with a 2-point surcharge in outer wind bands, except on runways. Calm routes cost 49–54, and even the relaxed perimeter route needs at least 112. These are host-model bounds; variable weather and pilot errors are handled by the separate ROM flight test. Report: `build/flight-simulator/validation-routes.json`.

`validate_flight_simulator.py --mask-rom <file> --language fr|en --seed 0..999` runs the actual source through map-number validation, its printed procedural map, radar confirmation/cancellation, cooldown, weather outage and recovery, and an ordinary flight through the terrain to a successful landing with the 99-point reserve and outer-band surcharge. Every printed tile is compared with an independent host calculation for the chosen seed. Actual matrix scans verify T+/T−, TEXT, margins, radar on both RELOC and REPEAT and held-key debouncing. Fixtures cover relief, runway heading, overspeed, stall, fuel exhaustion, map limits, low-forest fuel use and radar availability over water at H100/H150. Dense source line numbers are resolved through the generator label map. It verifies replay, clean exit, source preservation and runtime memory; paper and LCD images illustrate the bilingual guide. `--flight-only` isolates a host-piloted journey with ordinary controls, the actual weather/PRNG state and two radar fixes; it changes no program byte or flight variable. The pilot replans a calm route after every real step, predicting only the imminent wind. `--features-only` verifies both tower request types, cancelled radar requests, storm-paused deadlines, nonfatal expiry, scoring, 32-column HUD limits, wind-band entry/exit, runway exemptions and all four map exits. It uses explicit state/PRNG fixtures while keeping the real palette and source. `--no-captures` avoids shared guide-image writes during parallel checks. `--controls-only` isolates physical controls, speed bounds, both radar keys, the four calm takeoff steps and paused help. It also verifies the actual decoded palette, land/water probability thresholds using an identical PRNG sample, recurring variable-length storms and recovery windows with explicit aircraft/PRNG state fixtures. A pixel-level check covers radar visibility on every repeated tile at all quarter-cell offsets; mixed terrain and prior marks may still obscure a cross. `--quick` explicitly replaces only the initial map-ink entry with its final positioning routine. `--generation-only` executes the production BASIC row routine for seeds 1, 42 and 999 in an explicit POKE-capture caller harness (1,440 cells), then checks protected corridors, paired mountain halves and terrain coverage for all 999 map numbers in the host oracle. `--randomness-only` uses an explicit END-after-selection fixture and different opening-menu delays to verify three different random map numbers and terrains, even with the emulator's fixed timer registers. Fixture reports are separate from full unmodified-source reports. Outputs go to `build/flight-simulator/`.

`validate_3d_maze.py --mask-rom <file>` executes random map generation on the selected BASIC ROM, checks connectivity and reciprocal walls for all 100 cells, and verifies parent paths, perspective, custom LCD patterns, health, help, treasure, exit and cadence beyond 9,999 steps. `--generation-only --seed <integer>` isolates reproducible BASIC generation. `--natural --language fr --paper` and `--natural --language en --menu-polls 11` exercise unmodified game sources with ordinary movement: the initial menu advances the real ROM RNG, the actual generated world is compared to an independent DFS oracle, and the player must find a fragment and encounter the monster without teleports or forced placements. Every starting cell must have at least three internal passages; all four fragments must be in distinct quadrants and outside that cell. The different confirmation delays must produce different worlds. `--quick` uses an explicitly labelled host map fixture with diagnostic T/V keys to test short-range chase, losing pursuit beyond three passage steps, random wandering, same-view monster removal and all three sizes without repeating generation. All 148 drawing-bank combinations are also checked. Tests verify that program bytes remain unchanged. Four fragments exist in either display mode, one per quadrant; `--paper --quick` checks all four discoveries, 6,400 exact wall pixels per sector, captions, map/LCD restoration and suppression of repeat prints. Paper fixtures use the public movement controls, preserving the production RAM budget. Reports are written to `build/maze-3d/`.

`--quick --entities-only` isolates fragment visibility at one and two cells and concealment at three cells, wall occlusion, closest-entity priority, consecutive discoveries, and formerly invisible attacks at both left and right bends. Visible frontal contact remains dangerous. The paper fixture also checks letter/number alignment at native motor positions; `--paper-sectors 2` tests opposite sectors, including row 10 and a second print, without repeating the other two quadrants.
