# Firmware construction

HD6301 sources are in `../../src/`. The published firmware is **0.4.101-dev**, for S-70 and the documented serial-upgraded Typestar 6-II / S-61. Startup and serial transfers have been validated on both models; the new head-positioning shortcuts were confirmed on hardware on 24 November 2026. Its incremental pipeline extends .88 (`build_llist.py`) with .89's glyph-mask relocation fix, .91's separate paper-correction step, .92's reduced 1/4 gain and .93's continuous repeated glyphs and lossless font repacking. Ready-to-program images and resource statistics are in [firmware/0.4.101-dev](../../firmware/0.4.101-dev/README.md).

These scripts form an **incremental build pipeline**. Each stage checks the previous CPU image and symbol map before modifying the relevant ROM regions. `build.py` is the initial stage, rather than an independent build of the latest version. Intermediate images, manifests and reports live in the ignored `build/` directory.

Run scripts from the repository root. The existing pipeline requires the A09 assembler, the original Canon firmware and locally generated intermediate reports. It retains paths to the adjacent ROMReader research workspace. A standalone, configurable build remains a separate publication task. This reorganization changes no firmware bytes.

Some shared modules retain a `validate_` prefix because assembly helpers were developed alongside verification code; they remain here when construction stages import them. Release regression suites are in `../diagnostics/`; older research probes are stored in the ignored `_local/development/` tree.

The previous **0.4.100-dev image** uses `build_release_candidate.py`, followed by `../diagnostics/run_release_audit.py` and `prepare_release_candidate.py`. Packaging requires sixteen passing reports with the exact CPU-image hash: ROM control flow and ownership, immutable error strings, BASIC execution, editor/CRC/retention, serial protocols, cross-command state, graphics, sound and games. Full coverage and the remaining hardware checks are described in [the audit notes](../../docs/firmware-test-0.4.100.md). The independent `?FOR/NEXT` message fixes a shared suffix overwritten during earlier repacking. The image has 58 explicitly free ROM bytes and 5,951 empty BASIC RAM bytes. The packaged images and checksums are in `firmware/0.4.100-dev/`; the release notes separate software coverage from physical tests.

Archived intermediate releases may be supplied with `TYPESTAR_FIRMWARE_ARCHIVE` or the ignored `_local/build-inputs.ini` (`[inputs]`, `firmware_archive = /path/to/archive`). Output always remains in the project's generated `release/` folder.

The published **0.4.101-dev firmware** is built with `build_head_jog.py`. It extends the .100 construction with console-only CODE/margin chords, a signed carriage-phase counter at `$1B8E..$1B8F`, and a right-edge print check. `src/head-jog-layout.json` records a checked packing of the ROM islands; reconstruction needs no packing solver. The compact keyboard decoder is compared against all keys in 10 layouts, both I/II tables and Shift states. Shared workspace copies and compact history routines fund the addition. The retained Canon motor code outside the 75-byte phase-helper region remains unchanged; the replacement preserves all 64 ring transitions, registers and flags. Canon's temporary negative approach coordinates are counted rather than clipped. Width is checked for the complete band, including repeats, before its first block. Error 9 closes an attempted over-wide drawing rather than retaining it as a resource-preflight retry; failed printer transactions release their busy marker after cleanup.

Run `../diagnostics/run_release_audit.py --build head-jog`, then `prepare_head_jog.py`. Packaging requires 17 passing reports for the exact CPU hash, including physical-key repeat/release, bounds, retained program/editor state, text/graphics/LLIST/RUN registration, low-memory rejection and normal/instant paper checks. Ready-to-program images go to `firmware/0.4.101-dev/`. Head positioning was confirmed on hardware by the user on 24 November 2026. Run `prepare_head_jog.py --hardware-validated` to record that confirmation in this release; the default keeps a pending status for a fresh build. The .101 image has 57 explicitly free ROM bytes and 5,951 empty BASIC RAM bytes. The previous .100 images remain available.

The .101 audit also protects the complete `?GOSUB/RETURN` message. Its old seven-byte prefix had retained a reference to RETURN's retired keyword suffix. The replacement is independently allocated and covered by a strict `RETURN`-without-`GOSUB` case and all 26 error-string fixtures.

For .89, `build_glyph_mask.py` verifies the .88 image and the final row-mask table before changing its single immediate reference and version banner. `prepare_glyph_mask.py` requires a passing actual-ROM regression report for that exact candidate hash. It generates a 32 KiB IC8 image and a 64 KiB mirrored image; the .88 files remain available. Sparse sprites and one-hot rows are required checks: an all-black glyph alone can hide an incorrect mask table.

For .91, `src/paper-y-poststep.asm` hooks the successful PMMOVE commit (`FEED`, `MOVE`, `LLOCATE`). An accumulator at `$1B8D` distributes three separate one-unit forward corrections across eight reversals of at least two units. The complete native reverse approach is preserved. An extra movement re-enters the existing paper-call preparation; a completed nominal Y prevents recursive compensation. Single-unit reversals, forward travel, `ORIGIN` and `LSPACING` preserve the fraction; boot clears it. Font records and keyword spellings are repacked, sharing eight exact font-stream bytes without changing any decoded glyph. All 37 token pointers, 54 command entries, direct spelling references and the LIST suffix alias are updated and checked. Net cost from .89: 32 ROM bytes and one working-RAM byte; 70 explicit ROM bytes remain, with 5,951 empty BASIC bytes unchanged. Native motor-call and coil-state comparisons against the BASIC prototype gate packaging, together with all 95 decoded characters and X/Y checks. Mechanical slip, skew and timing still require a hardware test.

The unsuccessful .90 reverse-overshoot experiment is archived outside the public sources. It is not a prerequisite of .91, which retains .89's preparer and follows the separate-step BASIC prototype.

For .92, the shared assembly parameter `YPGAIN` is 64/256; .91 remains reproducible with 96/256. Reassembly verifies a single changed gain operand, plus one banner digit. All motor control flow, X commands, font/dictionary locations and memory allocations remain byte-identical to .91. Checks cover 3,840 fraction/distance combinations, three full accumulator cycles, and an actual four-round-trip interpreter run with exactly one extra forward call and zero commanded X drift. The same `XY CHECK` diagnostic is used on hardware without any BASIC-side compensation. Hardware trials on S-61/S-70 selected this smaller gain; the remaining mechanical error depends on paper transport and paper condition.

For **.93**, `build_glyph_repeat.py` starts from the verified .92 image. `src/paper-glyph-repeat.asm` adds `GLYPH A(first),width,height[,mode[,repeat]]` (also matrix sources), repeat 1..16 and mode 4 for large square pixels. One rendered band is reused for all copies; a 16×16 mode-4 motif needs 348 temporary bytes whether repeated once or ten times. Ten walls use two native horizontal sweeps. BREAK is polled between native blocks; empty bands are skipped. The .92 motor routines, serial core and Y gain are retained.

Space comes from lossless font run selection (`src/paper-font-runs-byte.asm`) and exact keyword sharing. All 95 decoded characters, 37 token entries and 54 command links are checked. The 32 KiB ROM has 61 explicitly free bytes; empty BASIC RAM remains 5,951 bytes. `prepare_glyph_repeat.py` gates 32 KiB socket and 64 KiB mirrored images on the exact candidate's native glyph/font/BREAK regression report. Studio includes the matching symbols and mode-4 glyph editing/import. The user has confirmed the continuous rows and updated games on hardware. Native checks additionally cover raster contents, buffer lifetime, BREAK and far-column registration; no quantified printing-speed claim is made.
